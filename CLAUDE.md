# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

REST API for the "Challenge PHP Hexagonal" (Prex): integrates with the GIPHY catalog and exposes four
services (login, search gifs, get gif by id, save favorite gif). Laravel 12 / PHP 8.3, Hexagonal
Architecture + DDD, OAuth2 via Passport, MariaDB. The human-facing documentation is `README.md` (Spanish);
code and comments are English.

## Environment

**There is no PHP, Composer or Node on the host** — every command runs inside the container:

```bash
make up                                    # build + start app (php-fpm), nginx, MariaDB
docker compose exec app php artisan ...    # anything else
```

The API listens on <http://localhost:8080>. Demo credentials created by the seeder:
`demo@prex.local` / `password`. `GIPHY_API_KEY` must be set in `.env` or the gif endpoints return 503.

## Architecture

`src/` holds the real code under the `Prex\` namespace; `app/` is only framework glue (two service
providers). Three bounded contexts plus a shared kernel, each split into `Domain / Application /
Infrastructure`:

| Context | Aggregate | Ports (interfaces in `Domain`) |
|---|---|---|
| `Auth` | `User` | `UserRepository`, `PasswordHasher`, `AccessTokenIssuer` |
| `Gifs` | `FavoriteGif` (+ `Gif` as a read snapshot) | `GifCatalog`, `FavoriteGifRepository` |
| `Audit` | `ServiceInteraction` | `ServiceInteractionRepository` |
| `Shared` | — | `Clock`; plus `UserId`, `Uuid`, base exceptions, HTTP helpers |

Flow of a request: route → `ForceJsonResponse` → `RecordServiceInteraction` (terminable) → `auth:api`
(Passport guard) → single-action controller → use case handler → port → adapter.

Key decisions that span files:

- **Composition root**: `app/Providers/HexagonalBindingsServiceProvider.php` is the *only* place where a
  port is bound to an adapter. New port ⇒ register it there.
- **Errors**: the domain never mentions HTTP. It throws `DomainException` subclasses that may implement the
  marker interfaces of `Shared\Domain\Exception` (`NotFound`, `Conflict`, `Unauthorized`, `Forbidden`,
  `ServiceUnavailable`); `Shared\Infrastructure\Http\Exception\ApiExceptionRenderer` maps them to status
  codes and to the single envelope `{"error": {"code", "message", "context"}}`. A plain `DomainException`
  (invariant violation) becomes 422. Note the shape: a domain error carries its payload under
  `error.context`, while a `ValidationException` spreads its fields under `error.errors`.
- **Auditing**: `RecordServiceInteraction` persists every call *after* the response is sent, and swallows
  its own failures (`report()`), so it can never break a successful request. The login endpoint has no
  authenticated user yet, so `LoginController` publishes the id through
  `Shared\Infrastructure\Http\RequestUserContext`, bound with `scoped()` (**not** `singleton()`: under a
  worker that outlives the request, one caller's identity would end up on the next one's audit row). Do
  **not** keep that state in a middleware property either: Laravel resolves a fresh middleware instance to
  run `terminate()`.
- **Duplicates are decided by the unique index**, not by the read before the insert: `(user_id, gif_id)` is
  the only atomic check, so `EloquentFavoriteGifRepository` translates its violation into the same `409` the
  sequential path returns. The handler still checks first, to keep a duplicate from spending GIPHY quota.
- **Identities** (`FavoriteGifId`, `ServiceInteractionId`) are UUIDs generated by the domain, not database
  auto-increments, so aggregates are complete before persistence.
- **GIPHY adapter** translates transport failures into domain exceptions (`GifCatalogUnavailable`,
  `GifNotFound`) and only retries transient ones (timeout, 5xx, 429) — never a 404/401. A `400/404/414/422`
  *about an id* is a `GifNotFound` (404), while a `401/403/429` means the provider is unusable (503).

## Rules enforced by tests (`tests/Architecture`, 21 tests)

These fail the build, so check them before restructuring:

- `Domain` imports no framework code (`Illuminate\`, `Laravel\`, `Symfony\`, `League\`, `GuzzleHttp\`,
  `Carbon\`) and never imports `Application` or `Infrastructure`.
- `Application` imports no framework code and no adapters — use cases talk to ports only.
- A bounded context may only import from itself and `Shared` (contexts never import each other).
- **Every interface must live under a `Domain/` directory.** Putting a contract in `Infrastructure` fails
  `every_port_lives_in_the_domain_layer`.

## Gotchas

- **Never add `env_file: .env` to the `app` service.** The project is bind mounted, so Laravel reads `.env`
  directly; injecting it as container environment shadows it (a real env var always wins over `.env`), and
  an empty `APP_KEY` breaks the app even after the entrypoint fills it in.
- **Never put `DB_CONNECTION`/`DB_DATABASE` in `phpunit.xml`.** PHPUnit writes `<env>` to `$_ENV`/`putenv()`
  only, while Laravel's env repository reads `$_SERVER` first — the suite would then run against the
  development database and truncate it. `tests/bootstrap.php` owns that decision (SQLite in memory, or
  MariaDB with `TEST_DB_CONNECTION=mariadb`).
- **Use `php artisan oauth:ensure-clients`**, not `passport:install`: the former is idempotent and safe to
  run on every container boot (the entrypoint does).
- **`expires_in` can be 1799**, not 1800: Passport derives it from the issuing instant. Assert the 30 minute
  contract, never an exact number of seconds.
- **In Postman scripts, `data` is a reserved identifier** (iteration data); `const data = …` throws
  "Identifier 'data' has already been declared" and silently kills the script.
- **The entrypoint runs as root, php-fpm serves as www-data.** `passport:keys` writes the pair 0600/0660,
  so anything the entrypoint creates under `storage/` must be chowned to www-data or the workers get
  `Key path "...oauth-public.key" does not exist or is not readable` (a 500 on every token operation).
  This only shows up on a fresh clone, never on a machine whose keys predate the container.
- **Anything a client sends must stay storable.** `Payload` normalises to valid UTF-8 in its constructor; the
  audit middleware swallows its own failures, so an unstorable payload means a request that silently leaves no
  trace at all (`?query=%FF` used to do exactly that).
- **Never echo a transport error message.** `$exception->getMessage()` from the HTTP client carries the full
  request URL, `api_key` included, and the GIPHY adapter's messages travel to the client and into the audit row.
- **GIPHY caps `q` at 50 characters** (414 beyond that, measured against the live API); `SearchTerm::MAX_LENGTH`
  exists to keep our validation and the provider's in sync.
- Tests fake GIPHY at the HTTP boundary (`Http::fake` via `tests/Concerns/FakesGiphy`), so the real adapter
  is exercised. Unit tests use the in-memory doubles in `tests/Doubles` and touch neither DB nor framework.

## Review findings, fixed

A second pair of eyes went through the code and ran 112 e2e cases; the fixes landed with a regression test each
(`a_payload_with_invalid_utf8_is_still_storable`, `the_unique_index_turns_a_lost_race_into_a_conflict`,
`a_transport_failure_never_leaks_the_api_key`, `an_unknown_email_costs_a_verification_too`,
`a_rejected_login_is_not_logged_as_an_incident`, …). One finding was left alone on purpose:
`PassportAccessTokenIssuer` re-reads the user that `findByEmail` already loaded. Avoiding that query means
faking an Eloquent model that Passport then writes a token for, which trades a real existence check for a
micro-optimisation - not worth it.

## Documented deviations from the challenge statement

Keep these — they are explained in README §12:

- `GIF_ID` / `ID` accept alphanumeric ids (GIPHY uses e.g. `3oEjI6SIIHBdRxXI40`), not just digits.
- `user_id` in "save favorite" must match the authenticated user, otherwise 403 (`favorite_user_mismatch`).
- Saving a favorite verifies the gif exists in the catalog (after the ownership and duplicate checks, which
  cost nothing), and responds `201` with the created resource (the statement left the output empty).
